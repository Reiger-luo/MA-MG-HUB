# MG Intelligence Hub：网站设计与审查速览

> 5 分钟入口，快照日期：2026-07-15。详细操作见 [MG-Intelligence-Hub-操作手册-v5.md](MG-Intelligence-Hub-操作手册-v5.md)。

## 产品边界

MG Intelligence Hub 是面向医学事务与中国大陆 MSL 的**公开证据决策支持和拜访准备来源**。它把 PubMed、指南/共识、监管、试验注册、会议来源和公开作者-机构线索组织成可追溯的准备材料。

它不是拜访记录、CRM、follow-up、互动历史或私有数据存储。网站不采集拜访笔记、团队反馈、内部专家标签或任何需要登录保存的个人数据。

## 设计原则

1. 证据先于叙事：所有公开文献必须先通过 MG-core 与 evidence I–V 门控。
2. 来源分频道：指南/共识、监管、注册和会议不能冒充 Oxford 文献证据。
3. 可追溯：判断、Signal、talking point 尽量回链 PMID、注册号或官方来源。
4. 公开最小化：前端只承载公开、必要的数据；full、缓存和内部材料留在本地。
5. 云端不降级覆盖：没有 full 时保留 last-good full-derived 产物和专家分片。
6. 决策支持而非自动结论：abstract-level 结果用于定位和提问，不替代全文医学审核。

## 页面任务

| 页面 | 核心任务 |
|---|---|
| 工作台 | 快速扫描近期信号和数据状态 |
| 情报中心 | 回答“最近发生了什么”，并区分文献与其他来源频道 |
| 诊治格局 | 回答“证据怎样影响治疗判断”，提供 Living Answers 提纲 |
| 知识库 | 浏览 full-derived 社区、图谱、证据矩阵和专题 |
| MSL 工作台 | China-only 专家检索、拜访前话题建议和 PMID 材料清单 |
| 数据状态 | 审查数量口径、产物时间、来源和管线健康 |

## 证据与来源频道层级

```text
PubMed MG-core + evidence I–V
  → 公开文献流 / 文献信号（可显示 Oxford 等级）

MG-core 指南/共识
  → guideline-consensus-cache / 指南共识频道（不显示 Oxford 等级）

中国监管 / ClinicalTrials.gov + ChiCTR / 会议主来源
  → 各自独立频道（状态或摘要级线索，不显示 Oxford 等级）
```

未知、非指南且无 evidence I–V 的 PubMed 记录不进入任何公开证据频道。

## MSL 建议工作流

1. 在情报中心确认 Signal 及其 PMID/官方来源。
2. 在 MSL 工作台按中国作者、机构和学术兴趣选择候选专家。
3. 组合纯学术或产品相关内容模块，生成拜访前话题建议。
4. 回到 PMID、指南原文、注册页或官方监管来源核查关键结论。
5. 在获批的外部系统中完成实际拜访记录；本站不保存任何拜访结果。

## 非目标

- 不建设拜访记录、follow-up、CRM 或互动历史。
- 不保存私有材料、内部专家标签、团队反馈或用户画像。
- 不把摘要级关联包装成全文级因果结论。
- 不在无 full 的云端运行中重建或缩小 full index、community、knowledge graph、中国作者网络和专家分片。
- 不在局部派生后伪造 `data/release-manifest.js`。

## 5 分钟审查顺序

1. 读本页“产品边界”和“非目标”（约 1 分钟）。
2. 打开情报中心，确认文献、指南、监管、注册、会议分频道（约 1 分钟）。
3. 打开 MSL 工作台，确认 China-only、只生成拜访前建议、不保存记录（约 1 分钟）。
4. 打开数据状态，对照 public rolling 与 semantic full 两套数量（约 1 分钟）。
5. 运行下方快速验证，确认门控、分片和发布边界（约 1 分钟）。

## 验证命令

python3 -m pytest -q

```bash

```

## 已知限制

- 文献、图谱和 Living Answers 主要基于 title/abstract/metadata，正式医学使用前需阅读全文。
- MG-core 与 evidence 分级为规则系统，仍需持续抽样审计。
- 2026-07-15 严格公开 recent 为 652 篇，其中中国相关 211 篇；`dashboard-data.js` 与 `china-intelligence.js` 已按该口径重建。full/语义底座为 10,672 篇，两者用途不同。
- 默认前端构建保留专家 manifest 及 China 8,958 / international 43,626 两个分片；仅显式 full 专家重建才改写它们。社区 recent 分片仍是独立的 full 社区构建口径。
- ChiCTR 自动访问可能受 WAF 影响，使用官方字段 last-good cache 或运营人员官方导出。
- `data/release-manifest.js` 当前不存在；只有真实 required-step 管线成功后才应生成。
