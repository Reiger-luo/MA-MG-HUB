# MA-MG-HUB 知识库社区分类精细化建议

生成日期：2026-06-29  
项目：MA-MG-HUB / MG Intelligence Hub  
文档定位：知识库与情报站之间的社区分类管理方案

---

## 0. 重新 review 后的核心判断

当前网站已经不是单纯的“知识库页面”。它已经有：

- 工作台：汇总各模块最新状态。
- 情报中心：文献速览、信号板、中国情报。
- 诊治格局：承接治疗进展、证据矩阵、竞争与中外差异。
- 知识库：abstract-level 图谱、证据矩阵、wiki 专题、跨库检索。
- MSL 工作台：面向医学事务行动。
- 数据状态：管线透明化。

所以问题不再是“加一个社区功能”，而是：

> 需要一个跨越知识库、情报中心、诊治格局和 MSL 工作台的 **医学事务社区分类层**。

这个社区层不是页面装饰，也不是普通 topic filter。它应该成为 PubMed 全库从“文献集合”转成“医学事务可行动知识”的中间语义层。

---

## 1. 当前结构的优势与不足

### 1.1 已有优势

| 已有模块 | 当前能力 | 社区层可以怎样增强 |
|---|---|---|
| 情报中心 / 文献速览 | 近 1 年文献筛选、证据等级、IF、China flag | 增加 community filter，让检索从“文献字段”升级到“医学问题” |
| 情报中心 / 信号板 | 14 天滚动窗口，规则筛选强/中/弱信号 | 按社区聚合信号，显示“哪些医学事务主题正在变化” |
| 中国情报 | 中国相关文献切片 | 中国作为 geo facet，嵌入各社区，而不是永远作为平行主题 |
| 知识库 / 图谱 | full PubMed abstract 共现图谱 | 社区可作为图谱染色、分组和解释层 |
| 知识库 / 证据矩阵 | 关系级 PMID 回链 | 社区内证据矩阵更便于定位临床问题 |
| 知识库 / 专题 | 从本地 wiki 生成 curated topics | 社区可判断哪些 PubMed 主题已被 wiki 消化，哪些未被策展 |
| 诊治格局 | 面向治疗策略和竞争格局 | 社区可作为治疗格局的主题骨架 |
| MSL 工作台 | 面向行动 | 社区状态可映射到拜访、简报、材料更新、专家沟通 |

### 1.2 当前不足

1. **知识库图谱依赖固定 concept dictionary**  
   当前 `build-knowledge-data.py` 基于 predefined conceptDefs 和 abstract 共现生成节点/边。优点是稳定，缺点是无法自动发现“医学事务上有意义但词典尚未定义”的新社区。

2. **信号板现在是规则驱动**  
   信号板已经能筛出强/中/弱，但更像单篇文献排序。它还没有回答：
   - 哪个医学事务社区本周正在升温？
   - 哪个社区出现了高证据冲击？
   - 哪个社区只是低质量噪音？

3. **wiki 专题层仍偏 efgartigimod-centered**  
   本地 wiki 的策展质量高，但覆盖范围与网站 PubMed 全库不等价。不能直接把 wiki 的内容结构搬到全站知识库。

4. **China 维度容易被误放为平行社区**  
   中国相关文献大部分是横向切片。除非讨论“中国真实世界路径 / 中国指南 / 中国准入 / 中国专家网络”，否则 China 更适合作为 facet。

## 2. 新定义：社区不是图谱 cluster，而是医学事务语义层

建议把“社区”拆成三种对象：

| 类型 | 作用 | 是否前台展示 | 维护方式 |
|---|---|---|---|
| 算法候选社区 | 从 abstract、concept、metadata、embedding 中发现自然聚类 | 不直接展示 | 自动生成 |
| 医学事务社区 | 面向临床问题、证据沟通、MSL 场景的稳定分类体系 | 主要展示 | DeepSeek Pro 设计 + 人工确认 |
| 新兴社区候选 | 新近增长、低置信度、尚未进入 taxonomy 的主题 | 在信号板/数据状态提示 | 普通模型发现，DeepSeek Pro 仲裁 |

最终前台展示的应是 **医学事务社区**。算法社区只是“发现工具”。

---

## 3. 模型分工：DeepSeek Pro 做架构，普通模型做批处理

### 3.1 不建议 DeepSeek Pro 逐篇分类全库

DeepSeek Pro 的上下文大，适合读全局、做 taxonomy、处理复杂边界。  
但如果让它逐篇给 10k+ abstract 分类，会把高级模型浪费在重复劳动上，也不利于持续周更。

更合理的分工：

| 工作 | 推荐模型 | 原因 |
|---|---|---|
| 读全库压缩包 / 候选社区包 | DeepSeek Pro | 长上下文、全局综合 |
| 设计 taxonomy、命名社区、写边界规则 | DeepSeek Pro | 需要医学事务结构判断 |
| 仲裁低置信度、跨社区冲突、新兴主题 | DeepSeek Pro | 需要上下文和边界推理 |
| 按固定 taxonomy 批量归类 PMID | 普通模型；可先 local/free，必要时升级 | 约束式分类，成本敏感 |
| 每周社区卡片摘要 | 普通模型 | 模板化摘要，可批量执行 |
| 关键版本最终 review | 高级模型 / 人工 | 避免 taxonomy 漂移 |

一句话：

> DeepSeek Pro 是 taxonomy architect；普通模型是 classification worker。

### 3.2 模型成本策略

- 全局分类体系设计：DeepSeek Pro。
- 稳定 taxonomy 下的批量分类：先用便宜普通模型；若输出不稳，再升级到 DeepSeek Pro 批处理。
- 高风险最终方案、前台信息架构和医学事务边界：由高级模型或人工 review。

## 4. 推荐的数据流程

```text
literature-full.json
        ↓
抽取 PMID pack：title / abstract / evidence / study_type / journal / IF / China / concept tags
        ↓
算法候选社区：embedding cluster + concept co-occurrence + metadata enrichment
        ↓
DeepSeek Pro：阅读候选社区与代表摘要，生成医学事务 taxonomy
        ↓
普通模型：按 taxonomy 批量归类所有 PMID
        ↓
低置信度 / 冲突 / 新兴主题 → DeepSeek Pro 仲裁
        ↓
生成社区数据层：taxonomy / assignments / cards / weekly / audit
        ↓
驱动：工作台、情报中心、知识库、诊治格局、MSL 工作台
```

| 文件 | 角色 | 是否推前端 |
|---|---|---|

## 6. 社区 taxonomy 的结构原则

### 6.1 三层结构

```text
主社区
  └── 子社区
        └── facets / 标签
```

不要做一层 flat taxonomy。否则后续会出现社区爆炸。

### 6.2 主社区：建议控制在 8–12 个

下面是初始建议，不是最终固定 taxonomy。最终版本应由 DeepSeek Pro 阅读全库候选社区后生成。

| 主社区 | 定义 | 典型 MSL 用途 |
|---|---|---|
| 治疗策略与新药进展 | FcRn、补体、传统免疫治疗、救援治疗、序贯/联合 | 治疗定位、产品沟通、竞品问答 |
| 临床亚型与人群分层 | AChR、MuSK、LRP4、seronegative、ocular、juvenile、elderly、thymoma | 专家拜访前准备、分层治疗讨论 |
| 疗效结局与疾病负担 | MG-ADL、QMG、MSE、缓解、复发、危象、QoL、激素减量 | 证据解读、疗效沟通、材料更新 |
| 安全性与用药管理 | 感染、AE、IgG、免疫原性、长期安全性、停药/换药 | 安全性沟通、风险管理 |
| 诊断、监测与预测 | 抗体检测、电生理、评分量表、生物标志物、预测模型 | 诊疗路径、专家教育 |
| 机制与转化医学 | FcRn biology、补体、胸腺、B/T cell、omics、遗传 | 机制沟通、KOL 深访 |
| 真实世界证据与临床路径 | registry、RWE、治疗路径、依从性、医疗资源 | 本土证据、路径优化 |
| 指南、共识与卫生经济 | guideline、consensus、HEOR、access、cost-effectiveness | 准入、政策、标准化诊疗 |
| 竞争格局与间接比较 | NMA、ITC、cross-drug comparison、治疗选择框架 | 竞品定位、医学策略 |
| 新兴/待审主题 | 近期增长但 taxonomy 尚未稳定吸收的主题 | 信号监测、下一轮策展 |

### 6.3 China 的处理原则

China 不应默认作为与所有主社区平行的社区。  
推荐处理为：

```text
primary_community = 真实世界证据与临床路径
geo_facet = China
china_context = 中国 RWE / 中国指南 / 中国准入 / 中国专家网络
```

只有当主题本身是中国临床实践差异、中国指南、中国准入、中国专家网络时，才形成独立子社区。

### 6.4 Facets 不要混入社区层

以下更适合作为横向标签，而不是社区：

| facet | 示例 |
|---|---|
| evidence_level | I / II / III / IV / V / VI |
| study_type | RCT / RWE / Case Report / Review / HEOR |
| geography | China / Global / Asia / Europe / US |
| product | efgartigimod / rozanolixizumab / nipocalimab / batoclimab / eculizumab |
| population | AChR+ / MuSK+ / ocular / juvenile / elderly |
| maturity | established / emerging / controversial / weak_signal |
| ma_action | monitor / brief / update_module / expert_visit / safety_update |

## 7. 社区 assignment schema

建议每篇 PMID 的社区归类输出如下：

```json
{
  "pmid": "34146511",
  "primary_community": "therapy_fcrn",
  "secondary_communities": ["outcome_response", "safety_use_management"],
  "facets": {
    "product": ["efgartigimod"],
    "population": ["gMG", "AChR-positive"],
    "geography": ["global"],
    "evidence_level": "II",
    "study_type": ["RCT"],
    "maturity": "established"
  },
  "ma_use_case": ["拜访前证据准备", "机制沟通", "产品疗效沟通"],
  "confidence": "high",
  "rationale": "Phase 3 randomized controlled trial of efgartigimod in generalized MG.",
  "needs_review": false
}
```

关键规则：

1. **必须有 primary community**，否则进入 unassigned queue。
2. **secondary communities 最多 2–3 个**，避免标签泛滥。
3. **rationale 必须引用 title/abstract 信息**，不能凭药物名猜测。
4. **低置信度必须标记 needs_review**，不要强行归类。
5. **病例报告只在有药物、安全性、中国、特殊人群或强机制信号时提高优先级**。

## 8. DeepSeek Pro 任务设计

### 8.1 输入包

不要直接塞原始全库 JSON。应先压缩成模型可读 corpus pack：

```json
{
  "pmid": "...",
  "title": "...",
  "abstract": "...",
  "journal": "...",
  "pub_date": "...",
  "evidence_level": "...",
  "study_types": [],
  "china_related": true,
  "concept_tags": [],
  "if": 0,
  "quartile": ""
}
```

再加候选社区摘要：

```json
{
  "candidate_id": "cluster_023",
  "size": 184,
  "top_terms": [],
  "top_drugs": [],
  "top_populations": [],
  "evidence_mix": {},
  "recent_growth": 12,
  "representative_pmids": []
}
```

### 8.2 DeepSeek Pro 输出

```json
{
  "taxonomy_version": "community_taxonomy_v1",
  "communities": [
    {
      "id": "therapy_fcrn",
      "title": "FcRn 靶向治疗：疗效、安全性与用药路径",
      "definition": "...",
      "include": [],
      "exclude": [],
      "subcommunities": [],
      "seed_pmids": [],
      "boundary_notes": [],
      "ma_use_cases": []
    }
  ],
  "facets": [],
  "ambiguous_rules": [],
  "new_community_threshold": "..."
}
```

DeepSeek Pro 的 prompt 应强调：

- 你不是做关键词聚类，而是设计医学事务分类体系。
- 社区必须服务 clinical question 和 MA action。
- China 多数情况下是 facet，不是平行主社区。
- 每个社区必须写 include / exclude / boundary notes。
- 允许保留 emerging candidate，不要强行并入成熟社区。

## 9. 普通模型批量分类任务设计

普通模型只做 constrained classification。输入包括：

- 固定 taxonomy。
- 每篇 PMID 的 title / abstract / metadata。
- 输出 schema。
- 强约束：不得创造新社区；无法判断则 `needs_review=true`。

建议每批 50–100 篇。批量输出 JSONL，便于失败重跑。

### 质量门禁

| 检查 | 目标 |
|---|---|
| unassigned rate | 初版可接受 5–10%，稳定后应 <5% |
| low-confidence rate | 初版可接受 10–20%，稳定后应 <10% |
| community imbalance | 单一社区不应吞掉过多无关文献；oversized 需拆分 |
| secondary label inflation | 平均 secondary communities 不应过高 |
| China facet consistency | China 不能既当 facet 又被误当主社区 |
| evidence mismatch | 高证据文献应优先进入可行动社区 |
| case-report noise | 病例报告不应主导治疗策略社区 |

## 10. 社区卡片设计

每个社区前台展示为 community card：

| 字段 | 含义 |
|---|---|
| 社区名 | 医学事务可读命名，不是算法 cluster 名 |
| 定义 | 一句话说明临床/医学事务问题 |
| 文献数 | 全库 PMID 数 |
| 近 14 天新增 | 情报中心联动 |
| 近 1 年新增 | 趋势观察 |
| 证据等级结构 | I–VI 分布 |
| 代表文献 | 高证据、高 IF、近期新增、里程碑文献 |
| 关联药物/机制/人群 | 来自 concept tags 与模型归类 |
| 中国相关占比 | geo facet |
| MSL 使用场景 | 拜访、机制、安全、竞品、材料更新 |
| 当前状态 | established / emerging / controversial / stale |
| gap flags | 缺 RCT、缺中国数据、缺长期安全性、证据冲突等 |

## 11. 如何进入现有网站模块

### 11.1 工作台

新增“社区动态”区块：

- 本周增长最快社区。
- 本周强证据冲击社区。
- 本周需要人工 review 的社区。
- 本周值得 MSL 跟进的社区。

示例：

```text
本周社区动态
- FcRn 靶向治疗：新增 6 篇，2 篇高证据，建议更新拜访简报。
- 安全性与感染风险：新增 3 篇，1 篇药物警戒，建议进入安全性材料更新队列。
- 中国真实世界路径：新增 4 篇，均为回顾性/单臂，作为观察信号。
```

### 11.2 情报中心

文献速览：

- 增加 community multi-select。
- 每篇文献卡片显示 primary community。

信号板：

- 从单篇排序升级为“社区聚合 + 单篇证据”。
- 高频主题从 keyword cloud 升级为 community heatmap。

中国情报：

- 不再只列中国文献。
- 展示各社区中的中国证据分布：FcRn、RWE、指南、专家网络、安全性等。

### 11.3 知识库

增加“社区视图”：

- 社区卡片列表。
- 社区内证据矩阵。
- 社区 ↔ concept graph 联动。
- 社区 ↔ curated topics 联动。
- 社区 ↔ PMID 列表。

图谱页可增加社区染色：

```text
节点颜色 = concept type
节点外圈 / 背景色 = dominant community
```

### 11.4 诊治格局

社区层成为诊治格局骨架：

- 治疗策略与新药进展 → 治疗路径。
- 竞争格局与间接比较 → 竞品定位。
- 安全性与用药管理 → 风险管理。
- 真实世界证据与临床路径 → 本土落地。
- 指南、共识与卫生经济 → 准入与标准化。

### 11.5 MSL 工作台

社区状态映射为行动：

| 社区状态 | MSL action |
|---|---|
| 高增长 + 高证据 | 生成拜访简报 |
| 高增长 + 低证据 | 标记为观察信号 |
| 竞品社区增强 | 更新竞品问答 |
| 安全性社区变化 | 更新安全性沟通材料 |
| 中国证据增加 | 更新本土证据包 |
| 与专家研究方向匹配 | 推荐专家拜访主题 |

### 11.6 数据状态

新增“社区分类健康”：

- taxonomy version。
- assignment coverage。
- unassigned PMIDs。
- low-confidence PMIDs。
- emerging candidates。
- 本周 drift / split / merge 建议。

## 12. 社区质量管理：每周 audit

每周管线应输出 community audit：

| Audit 项 | 触发条件 | 行动 |
|---|---|---|
| unassigned PMIDs | 普通模型无法归类 | 进入 DeepSeek Pro 仲裁 |
| low-confidence PMIDs | confidence=low | 抽样复核，必要时调 taxonomy |
| multi-community conflicts | 主/副社区冲突 | 修改边界规则 |
| emerging topic candidates | 近 14/30 天持续出现且未被覆盖 | 建立候选社区 |
| oversized community | 一个社区过大且内部主题分裂 | 拆分子社区 |
| stale community | 长期无新增 | 降低前台优先级 |
| China overlay gap | 中国文献多但无本土解释 | 生成中国 facet 摘要 |
| evidence mismatch | 高证据文献落在低价值社区 | 检查分类规则 |
| case-report noise | 病例报告主导社区 | 降权或移入特殊信号 |

## 13. 更新节奏

| 任务 | 频率 | 模型/方式 |
|---|---|---|
| 新文献社区归类 | 每周 | 普通模型批处理 |
| 社区卡片摘要更新 | 每周 | 普通模型 |
| 低置信度仲裁 | 每周或按需 | DeepSeek Pro |
| taxonomy 小修 | 每月 | DeepSeek Pro + 人工确认 |
| taxonomy 大修 | 每季度 | DeepSeek Pro 全局 review |
| 前台信息架构调整 | 按需 | 先讨论确认再编码 |

DeepSeek Pro 不需要每周重读全库。常规周更只读：

- 新增文献。
- 低置信度集合。
- community drift 报告。
- 每个社区代表性抽样。
- 当前 taxonomy。

## 14. 落地顺序

不直接改前台。先把社区层做成可审计的数据层。

### 先做后台数据

1. 从 `literature-full.json` 生成 `community-corpus-pack.jsonl`。
2. 生成算法候选社区 `community-candidates.json`。

## 15. 最终目标

社区层的目标不是“把文献分组”，而是让 MA-MG-HUB 回答更高层的问题：

| 现在的问题 | 社区层之后的问题 |
|---|---|
| 最近新增了哪些文献？ | 最近哪些医学事务社区正在变化？ |
| 这篇文献属于什么主题？ | 这篇文献会影响哪个临床/MA 问题？ |
| 哪些文献是中国相关？ | 中国证据在哪些社区中补足了本土叙事？ |
| 哪些图谱节点有关联？ | 哪些社区已经形成可行动证据，哪些只是弱信号？ |
| wiki 有哪些专题？ | PubMed 全库中哪些社区已被 wiki 策展，哪些仍是缺口？ |

最终架构可以概括为：

```text
PubMed 全库 = 原料
算法候选社区 = 发现工具
DeepSeek Pro taxonomy = 医学事务语义框架
普通模型 assignment = 可扩展执行层
community cards / weekly / audit = 网站业务层
工作台 / 情报中心 / 知识库 / 诊治格局 / MSL 工作台 = 行动入口
```

一句话结论：

> MA-MG-HUB 下一步最值得做的不是新增一个“社区页面”，而是建立一套全站共享的医学事务社区分类系统；它用 DeepSeek Pro 负责全局语义架构，用普通模型负责持续归类，用 audit 保证长期质量，并把社区动态反哺到情报、知识库、诊治格局和 MSL 行动。
