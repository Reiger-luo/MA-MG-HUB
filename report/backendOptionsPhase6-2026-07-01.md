# MA-MG-HUB Phase 6 后端选项评估

生成时间：2026-07-20 03:21:09
版本：`2026.07-phase6-backend-options`

## 1. 结论

**暂缓后端**。当前继续采用离线智能 + 静态发布；Phase 6 不启动生产后端。

核心能力已经能通过公开静态产物运行，触发后端的 5 类需求均未成为当前阻塞。

当前建议：继续 `GitHub Pages + 本地/Hermes 周更 + 静态公开产物`。

## 2. 后端触发条件

| 条件 | 当前状态 | 证据 | 什么时候需要后端 |
| --- | --- | --- | --- |
| 实时 LLM 问答 | 未触发 | 动态诊治格局已由离线脚本生成，前端不调用 LLM。 | 需要隐藏模型 key、限流、日志和引用校验时再启动。 |
| 实时语义搜索 | 未触发 | 当前使用 full-index、社区分片和静态图谱检索，未接入向量服务。 | 需要跨全文、自然语言问答或 embedding 排序时再启动。 |
| 用户私有笔记 | 未触发 | 公开站只展示公开数据产物；拜访记录和内部标签不进入仓库。 | 需要多人私有记录、跟进任务或专家标签时再启动。 |
| 多人协作 | 未触发 | 当前协作仍以 Git/Hermes/Codex 工作流为主。 | 需要浏览器内多人编辑、审阅队列或通知时再启动。 |
| 权限管理 | 未触发 | GitHub Pages 为公开展示层，无登录和权限分层。 | 需要区分公开、内部、个人笔记和管理员操作时再启动。 |

## 3. 选项比较

| 选项 | 推荐级别 | 适合场景 | 主要代价 | 平均分 |
| --- | --- | --- | --- | ---: |
| 继续 GitHub Pages + 本地/Hermes 周更 | 当前主路径 | 公开展示；静态数据产物；可追溯知识库；低运维成本 | 不支持私有用户数据；不适合实时 LLM key；交互智能依赖离线生成 | 4.4 |
| Cloudflare Worker + KV/D1 | 优先轻后端候选 | LLM API 代理；轻量权限；速率限制；公开缓存 | 复杂查询能力有限；D1 数据模型需提前设计；本地 full 仍不应直接搬上云 | 3.8 |
| Vercel Function | 适合作原型 | 快速 API 原型；LLM 代理；小规模服务端逻辑 | 与 GitHub Pages 部署面分离；持久化仍需外部数据库；长期运行任务不合适 | 3.0 |
| Supabase Edge Function + Postgres/Auth | 私有数据触发后再评估 | 用户登录；私有笔记；多人协作；审阅队列 | 数据治理复杂度最高；需要权限模型；公开站阶段过早引入会增加负担 | 3.8 |
| 本地 Hermes API | 本地完整分析和自动化主控 | 访问 full 本地库；长任务；定时周更；本地 LLM/embedding 实验 | 不适合作公开多人访问；需要本机在线；浏览器外部访问需额外安全边界 | 4.2 |

## 4. 决策规则

- 只要没有实时 LLM key、私有用户数据或多人协作，GitHub Pages 继续作为主展示层。
- 所有 LLM/embedding 能离线生成的结果优先离线生成，并以静态 JS 产物发布。
- 第一个轻后端只承担窄职责：LLM 代理、限流、日志或私有笔记之一，不一次性承载全站。
- 本地 full 数据库仍留在本地/Hermes，不直接上传到公开后端。

## 5. 后续路径

- **现在**：维持 GitHub Pages + 本地/Hermes 周更；数据状态页展示后端暂缓原因。
- **触发后**：若需要实时 LLM 问答，先做 Cloudflare Worker API 代理和 PMID schema 校验。
- **私有数据触发后**：若需要拜访记录、个人笔记或多人协作，再评估 Supabase Auth/Postgres。

## 6. 护栏

- 不得把 API key 放进 GitHub Pages 前端或公开仓库。
- 不得把本地 full abstract、私有拜访记录、专家内部标签直接推到公开后端。
- 后端生成的医学洞察必须保留 PMID、证据等级、社区、图谱节点和限制说明。
- 任何实时问答都必须区分 abstract-level 线索和正式医学结论。
