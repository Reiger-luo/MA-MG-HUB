# 第一部分：需求与框架

## 一、项目定位

**团队内部情报工作台**，以重症肌无力（MG）为核心。不对外公开，自己 + 团队可访问。

- 目标用户：自己（科研、医学事务、产业情报）+ 团队内部
- 运行周期：短期 1 年
- 更新频率：每周一次批量更新
- 基础设施成本：$0（GitHub Pages + Cloudflare 免费额度）
- 编程平台：Machine（Hermes Agent）全程为主，Codex 仅辅助复杂前端组件（按需）

## 二、核心架构决策

**混合模式：**

| 层级    | 方案                                          |
| ----- | ------------------------------------------- |
| 数据采集层 | Python 脚本，cron 定时触发，Hermes 环境运行             |
| 数据存储层 | 处理后生成 JSON 静态文件（无实时数据库）                     |
| 前端展示层 | 复杂数据走静态 JSON；交互筛选看板在浏览器端动态执行                |
| 部署    | GitHub Pages 托管，域名通过 Cloudflare DNS         |
| 后端    | 无持久后端服务器，数据更新 = 重新生成 JSON → git push → 重新部署 |

| Wiki 知识库                 | 内部积累的结构化内容                                     | 持续    |

## 四、页面结构

```
Dashboard  ← 三个核心区块
├── ① 本周文献热度趋势（计量学维度）
├── ② 诊治格局信号（诊断前沿 | 治疗更新 | 中外差异）
└── ③ 快速产出入口

7 个功能页面：

1. 文献情报       ← 统一入口，中国研究是筛选视图
   24h速递 / 计量学视图 / 学术内容报告 / 一键文献简报

2. 会议信息       ← AAN / EAN / AANEM 三大会议
   公开摘要自动抓取 / 付费Poster上传 / 摘要→全文跟踪

3. 临床试验       ← ClinicalTrials.gov + ChiCTR

4. 监管动态       ← 全球批准 / CDE-NMPA / 标签变更（时间线）

5. 竞争情报       ← FcRn / 补体 / B细胞 / 其他管线对比

6. 诊治格局       ← 最核心、最难
   诊断前沿 / 治疗进展 / 中外差异 / 证据矩阵
   逻辑不写死在代码里——LLM 提取层做：
   每次更新→喂新数据→LLM 按 prompt 抽信号→JSON→前端渲染

7. 数据状态       ← Data Ops
   更新日志 / 来源健康度 / 复核队列
```

## 五、设计决策备忘录

### 页面逻辑

- 文献和会议是平行板块，但同一研究可能先会议后全文 → 应有关联标记
- Dashboard 不堆统计数字，回答"这周该干什么"
- 中国研究是文献的子集，通过筛选/标签聚焦，不是独立页面

### 数据逻辑

- 诊治格局的信号从多源碎片综合分析而来 → LLM 提取层 + 固定 JSON schema
- 逻辑在 prompt 里可调，不在代码里写死
- 格局 JSON 每个更新周期从零重新生成，不累加旧数据

### 协作流程

- Hermes 会话有 90 轮限制 + 可能被打断 → 模块化迭代，不做一次性构建
- 每模块：讨论→决定→构建→验收→下一模块
- 跨会话通过 Hindsight + iCloud 文件恢复上下文
- Codex 仅在复杂前端组件时介入（Machine 总集成）

## 各阶段详情

### 阶段 0：基础设施

- **目标**：GitHub 账号就绪、SSH key 配置、空 repo 创建
- **启动动作**：确认 `gh auth status` 或 `ssh -T git@github.com` 正常
- **谁做**：Machine
- **输出**：空 repo URL
- **验收标准**：`git clone` 到本机能 push/pull
- **终止条件**：GitHub 不可用 → 换用其他 git 托管（GitLab / sourcehut）
- **讨论点**：repo 命名、公开仓库还是私有（GitHub Pages 需要公开或 Pro）

### 阶段 1：项目骨架

- **目标**：GitHub Pages 域名绑定，能在浏览器访问 `mg.yourdomain.com`
- **启动动作**：拿到域名 DNS 面板（Cloudflare Dashboard）访问权限
- **谁做**：Machine
- **输出**：`index.html` 占位页 + 站内目录结构
- **验收标准**：https 访问到页面
- **终止条件**：DNS 解析卡住 → Cloudflare Tunnel 作为后备方案
- **输出目录约定**（此阶段确定，后续沿用）：
  
  ```
  repo/
  ├── index.html              # Dashboard
  ├── pages/
  │   ├── literature.html     # 文献情报
  │   ├── conferences.html    # 会议信息
  │   ├── trials.html         # 临床试验
  │   ├── regulatory.html     # 监管动态
  │   ├── intelligence.html   # 竞争情报
  │   ├── landscape.html      # 诊治格局
  │   └── data-ops.html       # 数据状态
  ├── data/                   # 管线生成的 JSON
  ├── scripts/                # 抓取/处理脚本
  ├── assets/                 # CSS / JS / 图片
  └── README.md
  ```

### 阶段 2：数据管线

- **目标**：Python 脚本从 PubMed 抓取 MG 相关文献 → 输出结构化 JSON
- **启动动作**：讨论并确认检索词/过滤条件
- **谁做**：Machine（纯 Python，不需要 IDE）
- **输出**：`scripts/fetch-pubmed.py` + `data/literature-weekly.json`
- **验收标准**：脚本跑完，JSON 包含 PMID、标题、摘要、作者、期刊、日期、PMID
- **终止条件**：API 限频或改版 → 降级到 browser scraping
- **讨论点**：检索词（"myasthenia gravis"[Mesh] 还是关键词？）、字段范围、增量还是全量、是否复用 pubmed-search skill

### 阶段 3：文献情报页面

- **目标**：前端展示文献列表 + 筛选器（机制/时间/中国研究）
- **启动动作**：准备好阶段 2 输出的 JSON 样例（至少 10 条数据）
- **谁做**：Machine 搭建骨架和逻辑。如需复杂计量图表（发文趋势、期刊分布热力图）→ 由 Machine 启动 Codex 写这个图表组件，Machine 集成到页面
- **Codex 协作方式**：
  
  ```
  1. Machine 写好页面骨架 + 数据加载逻辑
  2. Machine 用 terminal 启动 Codex CLI
  3. Codex 接收任务：写一个 ECharts 热力趋势图，数据从 `data/literature-weekly.json` 读取
  4. Codex 输出组件文件到 `assets/charts/trend-heatmap.js`
  5. Machine 集成到 `pages/literature.html`
  6. Machine 验收：浏览器打开确认能跑
  ```
- **输出**：`pages/literature.html` + `assets/` 下的 CSS/JS
- **验收标准**：JSON 加载正常、筛选器工作机制确认、中国研究标签正常过滤
- **终止条件**：布局方案不满意 → 退回讨论再继续

### 阶段 4：会议版块

- **目标**：AAN/EAN/AANEM 摘要抓取脚本 + 会议页面
- **启动动作**：确认三大会议公开摘要的网址和格式（Neurology 增刊 / Eur J Neurol 增刊 / Muscle & Nerve 增刊）
- **谁做**：Machine（抓取脚本 + 页面均为本阶段编码主体）
- **Codex 协作方式**：本阶段不需要。如后续付费 poster 上传需要文件拖拽交互 → Machine 启动 Codex 写一个上传组件，存到 `assets/upload-handler.js`
- **输出**：`scripts/fetch-conferences.py` + `pages/conferences.html`
- **验收标准**：至少一个会议的摘要能正常展示
- **终止条件**：反爬严重 → 改为半自动（手动下载 PDF 增刊后脚本解析）
- **讨论点**：三大会议各自的抓取策略、摘要→全文关联逻辑（PMID 匹配）

### 阶段 5：临床试验 + 监管

- **目标**：ClinicalTrials.gov + FDA / NMPA 数据接入
- **启动动作**：讨论是否复用已有的 clinical-trials-search skill
- **谁做**：Machine（API 调用 + 页面均为本阶段编码主体）
- **Codex 协作方式**：本阶段不需要
- **输出**：`scripts/fetch-trials.py` + `scripts/fetch-regulatory.py` + `pages/trials.html` + `pages/regulatory.html`
- **验收标准**：试验列表 + 筛选器正常工作；监管时间线正常渲染
- **终止条件**：API 接口变更 → 改用备份数据源或手工维护缓存的 JSON
- **讨论点**：试验筛选范围（仅 MG？含其他神经免疫？）、监管动态源（openFDA / DailyMed / NMPA 官网）

### 阶段 6：竞争情报 + 诊治格局（核心）

- **目标**：LLM 提取层搭建，格局 JSON 自动生成 + 格局页面
- **启动动作**：对齐格局 JSON schema（含信号类型、中外差异判断规则）+ 提取 prompt 初版
- **谁做**：Machine 搭建 LLM 提取层和页面骨架。如需交互式证据矩阵（展开/折叠、多维度筛选、可拖拽对比）→ Machine 启动 Codex 写组件，存到 `assets/evidence-matrix.js`
- **Codex 协作方式**：
  
  ```
  1. Machine 先完成：格局 JSON schema、LLM 提取 prompt、格局 JSON 生成脚本
  2. Machine 写 `pages/landscape.html` 骨架 + 基本渲染
  3. 如果用户说"这个证据矩阵我想做得更交互"：
     a. Machine 启动 Codex CLI
     b. Codex 接收任务：写一个证据矩阵组件，数据从 `data/landscape-weekly.json` 读取
     c. Codex 输出到 `assets/evidence-matrix.js`
     d. Machine 集成到页面
  ```
- **输出**：格局提取脚本 + `pages/landscape.html` + `data/landscape-weekly.json`
- **验收标准**：每周更新后格局页面内容自动刷新
- **终止条件**：LLM 提取质量不达标 → 简化 schema（先只抽"治疗更新"和"中外差异"两类信号）或增加规则模板
- **讨论点**：提取 prompt 设计（什么算"格局信号"）、中外差异判定标准（获批状态/适应症/剂量/指南等级）、证据矩阵如何组织

### 阶段 7：Dashboard 精细打磨

- **目标**：Dashboard 三个区块完整实现 + 快速产出功能

- **启动动作**：确认 Dashboard 视觉风格方向（简洁卡片式 / 数据密集式 / 混合）

- **谁做**：Machine 做数据联动 + 区块布局。**强烈建议 Codex 介入** 做热力趋势图和交互式产出模板

- **Codex 协作方式**：
  
  ```
  1. Machine 准备好 Dashboard 需要的数据源（literature-weekly.json, landscape-weekly.json）
  2. Machine 启动 Codex CLI，交付 2 个任务：
  
     任务 A：写一个文献热度趋势图
       - 输入：data/literature-weekly.json
       - 输出：assets/charts/trend-heatmap.js
       - 要求：展示近 12 周发文趋势、热点关键词、机制分布
  
     任务 B：写一个快速产出模板
       - 输入：无（预定义模板）
       - 输出：assets/templates/quick-export.js
       - 要求：点击按钮后自动格式化当前数据为可复制的简报文本
  
  3. Codex 完成两个组件
  4. Machine 集成到 index.html
  5. Machine 验收：在浏览器打开确认所有区块加载正常
  ```

- **输出**：`index.html` 完整版 + `assets/charts/` 和 `assets/templates/` 下的组件文件

- **验收标准**：打开首页能看到文献热度趋势 + 格局信号 + 快速产出入口

- **终止条件**：Codex 做出来的组件不满意 → 退回 Machine 写简化版

- **Codex 介入**：热力趋势图、交互式产出模板（详见上方协作方式）

### 阶段 8：自动化流水线

- **目标**：每周 cron 自动运行数据管线 + 生成 JSON + git push → Pages 自动部署
- **启动动作**：确认通知渠道（微信 / 邮件 / Telegram）
- **谁做**：Machine（cron + git + Hermes 配置，这是 Machine 的核心能力）
- **Codex 协作方式**：本阶段不需要
- **输出**：Hermes cron job 配置 + 部署脚本 + 通知模板
- **验收标准**：每周自动更新完成并通知，无需手动操作
- **终止条件**：cron 环境问题（Hermes 不在线 / Python 依赖冲突）→ 降级为手动 `git push`
