---

## 1. 项目目标

MG Intelligence Hub 的目标不是“展示文献”，而是把医学事务团队的日常工作流串起来：

1. 发现本周值得看的信号
2. 快速查到证据与背景
3. 组织内容材料
4. 记录 MSL 拜访与 follow-up
5. 让每周更新沉淀为可复用的数据资产

当前优先级很明确：

- 先把静态站做成真正能用的工作台
- 再把本地数据工作站做稳
- 最后才考虑轻量后端和更高保真 LLM 增强

## 3. 当前运行口径

### 3.1 文献数据边界

- `data/literature-full.json`：本地分析底座，gitignore，不入仓库
- `data/literature-weekly.json`：每周临时输入，gitignore，不入仓库
- `data/literature-recent.js`：公开站近一年滚动源，入仓库
- `data/literature-recent.json`：可选调试缓存，默认不保留

### 3.2 周更顺序

1. 抓取 PubMed 近 14 天新增文献
2. 先做证据等级筛选
3. 没有证据等级的新文献直接剔除
4. 有证据等级的文献再补 IF/CAS
5. 本地有 full 时 upsert 到 `literature-full.json`
6. 由 full 派生 `literature-recent.js`
7. 生成 `signals-weekly.js`、`china-intelligence.js`、`expert-profiles.js`、`landscape-data.js`、`content-modules.js`、`dashboard-data.js`
8. 生成 `weekly-summary.md`
9. 生成 `pipeline-status.js`
10. Git push 并触发 Pages 部署

### 3.3 信号规则

- 信号继续使用脚本规则，不默认依赖 LLM
- 候选信号必须有证据等级
- `retraction / comment / author response` 类不进入信号
- 病例报告降权，只有真正有主题价值时才保留
- 规则优先保证稳定、可解释、可复现

## 7. 当前技术原则

1. 网站只消费公开 `.js` 产物，不直接碰敏感 key
2. 本机 Hermes 负责长期运行与定时任务
3. Codex 负责改代码、调管线、校准规划
4. LLM 默认只做增强，不做主路径依赖
5. 数据工作流优先于页面装饰
