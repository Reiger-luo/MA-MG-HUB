# MG Intelligence Hub v3.2 — 网站搭建蓝图

> 版本：v3.2
> 定位：MA-MG-HUB 医学事务 AI 变革引擎，围绕 MSL 工作流的主动赋能系统
> 文档用途：定义网站产品蓝图、数据机制、模块边界与落地顺序
> 执行状态：单独维护在 `report/项目执行状态与待办.md`

---

## 1. 核心目标

MG Intelligence Hub 不是一个文献展示站，而是一个给医学事务团队使用的工作站。

它要解决五件事：

1. 每周识别值得关注的 MG 学术信号
2. 快速查到支撑证据、专家背景与中国相关信息
3. 把证据转成可复用的内容模块
4. 帮 MSL 做拜访前准备、拜访后记录和 follow-up
5. 让每周更新沉淀为长期可分析的数据资产

---

## 2. 产品原则

1. 工作流优先于页面
2. Dashboard 回答“这周该做什么”
3. 信号默认由脚本规则生成，LLM 只做可选增强
4. 网站只读取公开 `.js` 数据，不直接持有敏感 key
5. full 数据留在本地工作站，公开站只部署轻量派生产物
6. MSL 拜访与内部专家标签不进入公开仓库
7. 先把静态站工作流做完整，再评估是否引入轻量后端

---

## 3. 系统角色分工

| 角色 | 职责 |
|:--|:--|
| GitHub Pages | 承载静态网站，展示公开数据产物 |
| 本地工作站 | 保存 `literature-full.json`，做 full 分析与本地周更 |
| Hermes | 适合承担长期定时任务、周报发送与本机自动化 |
| GitHub Actions | 保留轻量周更与 Pages 部署能力，可作为云端兜底 |
| Codex | 负责开发、调试、管线改造、规划校准 |
| LLM | 默认不参与周更主路径，仅在深度解读或内容生成时手动增强 |

## 4. 数据架构

### 4.1 文献主数据

| 文件 | 作用 | Git 状态 |
|:--|:--|:--|
| `data/literature-full.json` | 本地全量分析底座 | gitignore |
| `data/literature-weekly.json` | 每周临时输入 | gitignore |
| `data/literature-recent.js` | 网站近一年公开滚动源 | 入仓库 |
| `data/literature-recent.json` | 调试缓存 | 默认不保留 |

### 4.2 派生前端数据

| 文件 | 页面用途 |
|:--|:--|
| `data/signals-weekly.js` | 情报中心、Dashboard |
| `data/china-intelligence.js` | 中国情报 |
| `data/expert-profiles.js` | MSL 工作台、知识库 |
| `data/landscape-data.js` | 诊治格局 |
| `data/content-modules.js` | 内容工坊 |
| `data/dashboard-data.js` | 首页工作台 |
| `data/pipeline-status.js` | 数据状态页 |
| `data/weekly-summary.md` | 当前通讯渠道周报素材 |

### 4.3 周更机制

每次周更遵循固定顺序：

1. PubMed 抓取近 14 天新增 MG 文献
2. 对 weekly 文献先做证据等级筛选
3. 无证据等级的新文献不进入后续周更
4. 有证据等级的文献再补 IF/CAS
5. 本地有 full 时 upsert 到 `literature-full.json`
6. 从 full 派生 `literature-recent.js`
7. 生成各类前端 `.js` 数据
8. 生成周报与管线状态
9. 推送公开产物并触发 Pages 部署

GitHub Actions 没有 full 时，只使用现有 `literature-recent.js` 做轻量兜底。完整分析仍以本地 full 为准。

## 5. 网站信息架构

### 5.1 Dashboard

目标：成为每天打开后的工作入口。

需要展示：

- 本周强信号
- 待处理事项
- 中国相关变化
- MSL 快速入口
- 内容工坊入口
- 诊治格局入口
- 数据状态入口

设计重点：

- 少解释，多行动
- 信号按重要性排序
- 待办应能直接跳转到对应页面

### 5.2 情报中心

目标：承载 PubMed 文献、候选信号、中国情报。

核心能力：

- 文献筛选
- 证据等级过滤
- 强/中/弱信号展示
- 中国相关文献展示
- PMID 溯源

默认规则：

- 信号必须有证据等级
- `retraction / comment / author response` 不进入候选信号
- 病例报告降权
- LLM 不作为默认周更依赖

### 5.3 知识库

目标：统一检索文献、专家、证据问题。

核心能力：

- 文献检索
- 专家检索
- 证据问题检索
- 与 MSL 工作台、诊治格局互相跳转

后续增强：

- 接入 efgartigimod-wiki 检索
- 建立证据问题索引
- 支持按主题聚合材料

### 5.4 MSL 工作台

目标：把专家画像、拜访准备、拜访记录与 follow-up 串成闭环。

核心工作流：

1. 选择专家
2. 查看专家画像、近期发文、合作网络
3. 生成拜访前简报
4. 拜访后录入讨论点、需求、异议、索要材料
5. 生成 follow-up 清单
6. 下次回访时自动带入历史记录

本阶段先使用 localStorage 或本地 gitignore 数据验证价值。只有当持续录入成立后，才迁移到轻量后端。

### 5.5 内容工坊

目标：把文献证据和内容模块组织成可复用材料。

核心能力：

- 模板选择
- 模块选择
- 草稿组装
- 引用检查
- 按专家或场景生成材料包

内容模块应覆盖：

- 药理机制
- 临床证据
- 安全性
- 真实世界
- 竞品对比
- 指南与共识

### 5.6 诊治格局

目标：提供 MG 治疗格局、证据矩阵和竞争管线视图。

核心能力：

- 证据问题列表
- 支持/限制证据矩阵
- 治疗通路
- 中外差异
- 竞争管线
- 相关文献引用

下一步重点是让它更适合横向比较，而不是只展示静态数据。

### 5.7 数据状态

目标：让维护者快速判断数据管线是否正常。

展示内容：

- 数据源状态
- 公开数据产物
- full/recent 存储模式
- 最近生成时间
- 本地与云端运行口径

## 6. 自动化与维护

### 6.1 本地长期运行

本地工作站保留 full 数据和敏感/半敏感材料，因此适合承担完整周更：

- 拉取 PubMed
- 更新 full
- 生成 recent 与公开数据
- 生成周报
- commit / push
- 通过当前通讯渠道发送摘要

Hermes 可作为长期任务执行器。

### 6.2 云端兜底

GitHub Actions 保留以下能力：

- 手动触发周更
- 定时轻量更新
- 生成公开 `.js`
- 提交公开产物
- 触发 Pages 部署

云端不保存 full，不承担重分析。

---

## 7. 合规与数据隔离

| 数据 | 处理方式 |
|:--|:--|
| PubMed 文献公开字段 | 可入公开 `.js` |
| IF/CAS 缓存 | 可入仓库 |
| 专家公开画像 | 可入公开 `.js` |
| 专家内部标签 | gitignore 或后端 |
| 拜访记录 | 不入公开仓库 |
| Follow-up backlog | 不入公开仓库 |
| LLM 缓存与成本日志 | gitignore |

---

## 8. 建设顺序

### 第一优先级：MSL 工作台闭环

要把“专家画像”变成真正的拜访工作台：

- 新拜访简报
- 回访简报
- follow-up 状态
- 专家索要材料
- 本地拜访记录
- 下次拜访自动带入历史

### 第二优先级：内容工坊实用化

要让内容模块可被真实组合：

- 模板与模块更清晰
- 引用检查更可见
- 草稿可以围绕专家/主题生成
- 材料篮可复用

### 第三优先级：诊治格局工作台化

要让证据和竞争格局更适合比较：

- 证据问题聚合
- 文献支持/限制关系
- 药物与机制横向对比
- 中国差异单独维护

### 第四优先级：Dashboard 整合

Dashboard 应成为所有工作流入口：

- 强信号
- follow-up
- 待确认模块
- 待确认诊治格局
- 数据管线状态

---

## 9. 轻量后端触发条件

只有满足以下条件才引入后端：

1. MSL 拜访记录有持续录入价值
2. 多人协作确实需要共享状态
3. localStorage 或本地文件已经阻碍使用
4. 需要隐藏 LLM key 并提供实时生成能力

候选方案：

- Cloudflare Workers + KV/D1
- Vercel Functions
- 其他轻量 API 层

---

## 10. 验收标准

一个可用的 MA-MG-HUB 应满足：

1. 每周自动更新公开文献与候选信号
2. 信号可解释、可溯源、可过滤
3. MSL 能从专家页进入拜访准备
4. 拜访后能形成 follow-up
5. 内容工坊能组装可引用材料
6. 诊治格局能支持横向比较
7. Dashboard 能告诉用户下一步该做什么
8. 敏感数据不进入公开仓库

---

## 11. 当前决策

- 继续使用脚本规则生成信号，减少 LLM 依赖
- weekly 新文献先补证据等级，无等级不进入后续
- IF/CAS 只对有证据等级的新增文献补充
- full 留在本地，recent.js 作为公开站滚动源
- `项目规划-v3.2.md` 作为蓝图维护
- `项目执行状态与待办.md` 作为施工状态维护
