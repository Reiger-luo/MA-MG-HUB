## 一、核心理念（不变）

MG Intelligence Hub 是**情报驱动型**系统 — 用户（MSL / MA）在系统中工作，系统实时增强用户。四大工作流：情报感知 → 知识管理 → 学术产出 → MSL 闭环。

```
┌──────────────────────────────────────────────────┐
│                  MG Intelligence Hub v3.1          │
│                                                    │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────┐ │
│  │ 情报感知   │  │ 知识管理   │  │ 学术产出   │  │ MSL│ │
│  │ (Signal)  │  │ (Know.)  │  │ (Content)│  │ 闭环│ │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └──┬─┘ │
│       └──────────────┼──────────────┼──────────┘    │
│                      ▼              ▼                │
│              ┌────────────────────────┐              │
│              │  LLM 引擎层 + 数据管线   │              │
│              └────────────────────────┘              │
└──────────────────────────────────────────────────┘
```

### 关键设计原则（修订版）

1. **工作流优先于页面** — 先画用户日常流程，再决定页面结构
2. **信号驱动，不展示驱动** — Dashboard 回答"这周该干什么"
3. **LLM 做提取不做生成** — 提取/归类/结构化交给 LLM；最终产出的内容和判断由人决定
4. **渐进可部署** — 每阶段独立可用
5. **中国优先** — 所有情报通道都有中国独立视角
6. **反馈闭环** — MSL 使用行为反哺系统优化
7. **🆕 LLM 层统一封装** — 所有 LLM 调用走同一客户端（模型/重试/成本/缓存）
8. **🆕 数据合规隔离** — 公开数据入仓库，敏感数据（拜访/专家内部标签）走 gitignore 或后端

## 二、四大工作流详解

### 工作流 A：情报感知（Signal Intelligence）

| 维度 | 当前状态 | 目标 |
|:--|:--|:--|
| PubMed 文献 | ✅ 14天窗口抓取+展示 | 增加**新研究信号提取**（什么机制热了、哪个靶点有突破） |
| 会议信息 | ⏳ 待启动 | 公开摘要（AAN/EAN/AANEM）自动抓取 → 信号入库 |
| 中国信号 | ✅ 全库 1,866 篇可过滤 | PubMed 中国研究过滤 + 手动录入指南/政策更新 |
| MSL 一线情报 | ❌ 无 | 拜访后录入 → LLM 自动归类（证据缺口/观念变化/竞争动态） |
| 监管动态 | ⏳ 待启动 | FDA/NMPA 批准时间线，自动关联到相关文献和试验 |

**核心理念：** 情报不是"这周发了哪些文章"的展示，而是**"什么在变化"的信号推送**。

**输出形态：**
- Dashboard 的"本周信号"区块 — 每次打开看到 3-5 条值得关注的变化
- 每周自动简报（支持飞书 webhook 推送）
- 信号按强度/紧急度排序

### 工作流 B：知识管理（Knowledge Foundation）

| 维度 | 当前状态 | 目标 |
|:--|:--|:--|
| efgartigimod-wiki | ✅ 900页，独立存在 | 打通：Wiki 知识直接可被 HUB 检索/引用 |
| 暗数据 | ❌ 无 | MSL 访谈录音/笔记 → 自动结构化入库 |
| 文献回填 | ✅ 全库 68% 有证据等级、67% 有 IF | 增加**证据矩阵** — 某个问题有哪些证据支持/反对 |
| 专家知识库 | ✅ 39,334 作者基础数据 | 专家画像 + 拜访记忆时间线 + Follow-up 请求清单 |

**核心理念：** 知识是**可检索、可关联、可复用、带记忆**的资产。

### 工作流 C：学术内容产出（Content & Creation）

| 维度 | 当前状态 | 目标 |
|:--|:--|:--|
| 快速简报 | ✅ 一键生成（简报篮） | 增加**模板选择**（文献速递/竞品简报/会议摘要集） |
| 内容模块化 | ❌ 无 | 核心模块库：药理模块、临床数据模块、安全性模块、指南比较模块 |
| 按需组装 | ❌ 无 | 选择模板 → 选模块 → 输入参数 → 生成初稿 → 人工终审 |
| 合规校验 | ❌ 无 | 自动检查引用来源、数据一致性、声明格式 |

**核心理念：** 内容模块化 + 按需组装，让 MSL 在 10 分钟内生成个性化的学术材料。

### 工作流 D：MSL 学术互动闭环（Medical Engagement Loop）

**最核心、最能直接提升 MSL 团队价值**的工作流。

**核心设计：记忆感知的循环模式。** 区分**新拜访**与**回访**，让每次拜访都建立在真实的历史互动上，形成反馈→衍生→行动的飞轮。

```
                    ┌──────────────────────────────────────────┐
                    │              专家知识库                    │
                    │  发文历史 · 合作网络 · 画像               │
                    └──────────┬──────────────────┬────────────┘
                               │                  │
          ┌────────────────────┘                  └──────────────────┐
          ▼                                                          ▼
┌─────────────────────────────┐                     ┌─────────────────────────────┐
│  新拜访（首次/隔了很久）     │                     │  回访（有历史互动）          │
│  ① 专家画像概览              │                     │  ① 上次拜访纪要回顾          │
│  ② 近期热点关联性分析        │                     │  ② Follow-up 清单（自动追踪）│
│  ③ 学术合作机会提示          │                     │  ③ 专家索要材料准备度        │
│                              │                     │  ④ 新 Topic 衍生信号          │
│  → 生成「全新拜访简报」       │                     │  → 生成「跟进拜访简报」        │
└─────────────────────────────┘                     └─────────────────────────────┘
                               │                  │
                               └────────┬─────────┘
                                        ▼
                              ┌──────────────────┐
                              │    拜访结束后     │
                              │  结构化表单录入    │
                              │  LLM 归类 → 信号   │
                              └────────┬─────────┘
                                       │
                                       ▼
                     ┌──────────────────────────────────────┐
                     │  专家知识库更新 · 一线证据入库 · 团队汇总 │
                     └──────────────────┬───────────────────┘
                                        └────→ 成为下次拜访的「记忆输入」
```

**"回访"模式的核心价值：**

| 要素 | 新拜访 | 回访 |
|:--|:--|:--|
| 起点 | 专家画像+热点 | 上次拜访纪要 |
| 追踪项 | 无 | Follow-up 清单 |
| 准备度 | 通用材料 | 专家索要的具体数据/文献 |
| 衍生信号 | 泛泛的热点 | 基于上次讨论自然衍生的新 topic |
| 关键差异 | 一次性 | **循环——本次产出成为下次输入** |

**⚠️ 成败关键（v3 新增提示）：** 此闭环的价值完全依赖**团队持续录入拜访数据**。若录入率低，回访简报退化为"画像+热点"。阶段 3 采用先做最小闭环 MVP 的策略（见阶段 3）。

## 三、技术架构（修订版）

### 运行形态：静态站 + 轻量后端

```
┌─────────────────────────────────────────────────────────┐
│                    用户浏览器                             │
│  GitHub Pages 静态站（HTML/CSS/原生JS + Alpine.js）       │
│  数据：.js 文件（literature/signals/expert/landscape）    │
└──────────────┬───────────────────────┬──────────────────┘
               │ 只读加载 .js          │ 交互（POST）
               ▼                       ▼
┌──────────────────────┐   ┌─────────────────────────────┐
│  GitHub Pages        │   │  轻量后端（阶段3 MVP后按需）   │
│  （展示层，只读）     │   │  Cloudflare Workers /        │
│                      │   │  Vercel Functions            │
│  文献/信号/格局展示   │   │  · LLM 调用代理              │
│  专家画像展示         │   │  · 拜访记录写入（KV/D1）      │
│                      │   │  · 内容组装                  │
└──────────────────────┘   └─────────────────────────────┘
                                       │
                                       ▼
                           ┌─────────────────────────────┐
                           │  LLM API（DeepSeek-V3）       │
                           └─────────────────────────────┘
```

**职责划分：**
- **静态站（GitHub Pages）**：所有"看"的功能 — 文献浏览、信号板、专家画像展示、证据矩阵展示、Dashboard
- **轻量后端**：所有"写"和"实时生成"的功能 — 拜访记录录入、简报生成、内容组装、LLM 调用代理（隐藏 API key）

### LLM 引擎层（新增 — 阶段 0）

**核心：所有 LLM 调用走统一封装，避免每个脚本各自处理。**

```
scripts/llm_client.py
├── 统一调用接口：llm_complete(prompt, model, temperature)
├── 重试机制（指数退避，最多 3 次）
├── 本地缓存（prompt hash → 响应，避免重复调用）
├── 成本日志（token 计数 + 累计花费）
└── 模型路由（高频低质 → DeepSeek-V3；低频高质 → 更强模型）
```

**配置管理：**
- API key 存环境变量（本地）/ GitHub Actions Secrets（管线）
- 模型选择：主用 DeepSeek-V3（OpenRouter 路由），成本可控
- 缓存目录：`data/.llm_cache/`（gitignore）

### 数据管线流程

```
每周管线（GitHub Actions cron）：
  fetch-pubmed → full.json
    → study-classification (证据等级)
    → journal-metrics (IF/分区)
    → llm-signal-extraction（LLM 逐篇提取）
    → signal-aggregation（跨文献聚合）
    → build-expert-profiles
    → build-china-intelligence
    → extract-landscape-signals
    → build-evidence-matrix
    → split-recent-data → recent.js + 各 .js
    → module-update-check
    → git push（自动部署）

MSL 拜访（按需，先本地存储）：
  visit-input（前端表单）
    → llm-structure（自由文本→结构化）
    → 本地写入（data/visit-records.json，gitignore）
    → signal-update + expert-profile-update

  （阶段 3 MVP 验证后，按需迁移到轻量后端）

内容产出（按需，先本地组装）：
  select-template + select-modules
    → llm-compose（组装初稿）
    → compliance-check
    → human-review → final output

  （阶段 4 验证后，按需引入后端加速）
```

**特性说明：**

| 特性 | 实现 |
|:--|:--|
