## 一、核心理念转变

**v1 本质：** 数据展示型 — 我有 MG 数据，展示给你看。用户被动消费。

**v2 本质：** 情报驱动型 — 围绕医学事务四大工作流的主动赋能系统。用户（MSL / MA）在系统中工作，系统实时增强用户。

```
┌──────────────────────────────────────────────────┐
│                  MG Intelligence Hub v2            │
│                                                    │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────┐ │
│  │ 情报感知   │  │ 知识管理   │  │ 学术产出   │  │ MSL│ │
│  │ (Signal)  │  │ (Know.)  │  │ (Content)│  │ 闭环│ │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └──┬─┘ │
│       └──────────────┼──────────────┼──────────┘    │
│                      ▼              ▼                │
│              ┌────────────────────────┐              │
│              │    数据管线 + LLM 引擎    │              │
│              └────────────────────────┘              │
└──────────────────────────────────────────────────┘
```

## 二、四大工作流详解

### 工作流 A：情报感知（Signal Intelligence）

| 维度        | 当前（v1）       | 目标（v2）                                  |
|:--------- |:------------ |:--------------------------------------- |
| PubMed 文献 | ✅ 14天窗口抓取+展示 | ✅ 同左，增加**新研究信号提取**（什么机制热了、哪个靶点有突破）      |
| 会议信息      | ❌ 待启动        | 公开摘要（AAN/EAN/AANEM）自动抓取 → 信号入库          |
| 中国信号      | ❌ 无          | ChiCTR + CDE + 中国指南更新 + 中文核心期刊。这是独立信号通道 |
| MSL 一线情报  | ❌ 无          | 拜访后录入 → LLM 自动归类（证据缺口/观念变化/竞争动态）        |
| 监管动态      | ❌ 待启动        | FDA/NMPA 批准时间线，**自动关联到相关文献和试验**         |

**核心理念：** 情报不是"这周发了哪些文章"的展示，而是**"什么在变化"的信号推送**。

**输出形态：**

- Dashboard 的"本周信号"区块 — 每次打开看到 3-5 条值得关注的变化
- 每周自动简报（支持微信/飞书推送）
- 信号按强度/紧急度排序，MSL 知道该关注什么

---

### 工作流 B：知识管理（Knowledge Foundation）

|| 维度 | 当前（v1） | 目标（v2） |
|:--|:--|:--|
|| efgartigimod-wiki | ✅ 900页，独立存在 | 打通：Wiki 知识直接可被 HUB 检索/引用 |
|| 暗数据 | ❌ 无 | MSL 访谈录音/笔记 → 自动结构化入库 |
|| 文献回填 | ✅ IF/分区/证据等级 | 同左，增加**证据矩阵** — 某个问题有哪些证据支持/反对 |
|| 专家知识库 | ❌ 无 | 专家画像 + 拜访记忆时间线 + Follow-up 请求清单 |

**核心理念：** 知识不是"堆在那里的文件"，而是**可检索、可关联、可复用、带记忆**的资产。

**核心资产：**

1. **文献资产库** — 已有的，持续优化
2. **Wiki 知识图谱** — Obsidian 和 HUB 打通，双向检索
3. **专家知识库** — 每位专家的学术画像（谁在做什么、关注什么、和谁是合作者）
4. **一线证据库** — MSL 拜访输出的结构化信息

### 工作流 C：学术内容产出（Content & Creation）

| 维度    | 当前（v1） | 目标（v2）                          |
|:----- |:------ |:------------------------------- |
| 快速简报  | ✅ 一键生成 | 同左，增加**模板选择**（文献速递/竞品简报/会议摘要集）  |
| 内容模块化 | ❌ 无    | 核心模块库：药理模块、临床数据模块、安全性模块、指南比较模块  |
| 按需组装  | ❌ 无    | 选择模板 → 选模块 → 输入参数 → 生成初稿 → 人工终审 |
| 合规校验  | ❌ 无    | 自动检查引用来源、数据一致性、声明格式             |

**核心理念：** 不是 AI 帮你写稿，而是**内容模块化 + 按需组装**，让 MSL 在 10 分钟内生成个性化的学术材料。

**典型场景：**

- MSL 要拜访一位专家 → 打开系统选"拜访材料模板" → 系统自动填充该专家相关文献 + 最近热点 → MSL 调整后生成
- 区域学术会需要一份 MG 治疗进展 PPT → 选"区域学术会模板" → 勾选模块（Efgartigimod/补体/B细胞/指南更新）→ 生成初稿

### 工作流 D：MSL 学术互动闭环（Medical Engagement Loop）

这是**最核心、最能直接提升 MSL 团队价值**的工作流。

**核心设计：记忆感知的循环模式。** 系统不是每次都给一份"专家画像+近期热点"的通用简报，而是区分**新拜访**与**回访**，让每次拜访都建立在真实的历史互动上，形成反馈→衍生→行动的飞轮。

```
                    ┌──────────────────────────────────────────┐
                    │              专家知识库                    │
                    │  发文历史 · 会议演讲 · 合作网络 · 画像     │
                    └──────────┬──────────────────┬────────────┘
                               │                  │
          ┌────────────────────┘                  └──────────────────┐
          ▼                                                          ▼
┌─────────────────────────────┐                     ┌─────────────────────────────┐
│  新拜访（首次/隔了很久）     │                     │  回访（有历史互动）          │
│                              │                     │                              │
│  ① 专家画像概览              │                     │  ① 上次拜访纪要回顾          │
│  ② 近期热点关联性分析        │                     │  ② Follow-up 清单（自动追踪）│
│  ③ 学术合作机会提示          │                     │  ③ 专家索要的材料/数据准备度  │
│                              │                     │  ④ 新 Topic 衍生信号          │
│  → 生成「全新拜访简报」       │                     │  → 生成「跟进拜访简报」        │
└─────────────────────────────┘                     └─────────────────────────────┘
                               │                  │
                               └────────┬─────────┘
                                        ▼
                              ┌──────────────────┐
                              │    拜访进行中     │
                              │  智能助手实时参考  │
                              │  关键文献 · 互动建议│
                              └────────┬─────────┘
                                       │
                                       ▼
                              ┌──────────────────┐
                              │    拜访结束后     │
                              │  结构化录入反馈    │
                              │  LLM 归类 → 信号   │
                              └────────┬─────────┘
                                       │
                                       ▼
                     ┌──────────────────────────────────────┐
                     │  专家知识库更新（时间线 / 互动历史）    │
                     │  一线证据库入库（信号 → 知识管理）      │
                     │  团队信号汇总（共性趋势 → 策略层）      │
                     └──────────────────┬───────────────────┘
                                        │
                                        └────→ 成为下次拜访的「记忆输入」
```

**"回访"模式的核心价值：**

| 要素       | 新拜访     | 回访                                       |
|:-------- |:------- |:---------------------------------------- |
| **起点**   | 专家画像+热点 | 上次拜访纪要                                   |
| **追踪项**  | 无       | Follow-up 清单（专家之前提了什么、我们要交付什么）           |
| **准备度**  | 通用材料    | 专家索要的具体数据/文献/证据，系统自动标记"已准备/待准备"          |
| **衍生信号** | 泛泛的热点   | 基于上次讨论自然衍生的新 topic（如上次提了某机制 → 这周该机制有新文献） |
| **关键差异** | 一次性     | **循环——本次产出成为下次输入，信号持续累积**                |

**技术实现：**

- **专家画像**：PubMed 发文 + ClinicalTrials 参与 + 会议演讲 → 构建学术兴趣向量
- **拜访记忆**：每次拜访的结构化输出自动关联到专家档案，形成时间线
- **回访简报生成**：LLM 读取该专家全部历史拜访 → 提取未完成的 follow-up + 新衍生的相关信号 → 组装简报
- **Follow-up 追踪**：系统维护一个"专家请求清单"（KOL request backlog），每次回访前自动提示哪些已兑现、哪些待跟进
- **拜访后录入**：结构化的表单（口语转写 + LLM 归类），比自由文本录入更易复用
- **团队汇总**：所有 MSL 的拜访信号合并 → 发现共性趋势 → 调整下月策略

### 11.2 拜访记录数据结构

**核心原则：** 结构化 > 自由文本。口语化内容 LLM 转结构化，但入库的是结构化字段。

```json
{
  "visit_id": "v_20260610_001",
  "expert_id": "expert_001",
  "expert_name": "张三",
  "msl_name": "李明",
  "date": "2026-06-10",
  "type": "回访",
  "location": "北京协和医院",

  "pre_brief": {
    "generated_at": "2026-06-09",
    "content": "..." 
  },

  "discussion": {
    "topics": [
      {
        "topic": "FcRn 长期安全性",
        "expert_view": "专家关注...",
        "our_response": "我们提供了...",
        "follow_up_needed": true,
        "follow_up_items": ["提供 2 年随访数据", "安排与医学部电话会"]
      }
    ],
    "new_signals": [
      {"type": "观念变化", "content": "专家对补体抑制剂态度从观望转积极"}
    ],
    "materials_requested": [
      {"item": "Efgartigimod 日本真实世界数据", "status": "待准备", "deadline": "2026-06-20"}
    ]
  },

  "post_summary": {
    "key_takeaways": ["...", "..."],
    "next_visit_suggested": "2026-07-10",
    "next_topics": ["补体抑制剂头对头数据", "医保谈判进展"]
  }
}
```

**关键字段：**

- `type`: "新拜访" / "回访" — 决定简报生成模式
- `discussion.topics[].follow_up_needed` — 是否生成 follow-up 任务
- `materials_requested[].status` — "待准备"/"已发送"/"已收到反馈"
- `new_signals` — LLM 自动提取，归入全局信号库

### 11.3 拜访前简报生成

**新拜访模式：**

```
输入：专家画像（PubMed 回填）+ 本周情报信号
输出：
  ① 专家概览（发文/兴趣/合作者）
  ② 近期热点关联（该专家领域内的本周信号）
  ③ 学术合作机会（共同作者/重叠研究方向）
```

**回访模式（核心差异）：**

```
输入：上次拜访记录 + 本周情报 + 专家画像更新
输出：
  ① 上次拜访纪要回顾（自动摘要）
  ② Follow-up 清单（哪些已兑现 / 哪些待跟进 / 哪些超时）
  ③ 专家索要材料准备度（系统自动标记状态）
  ④ 新 Topic 衍生信号（基于上次讨论 + 本周新情报）
```

**关键设计：** 回访简报不是"重新生成一份"，而是**"基于记忆的延续"**。Follow-up 清单是系统自动维护的，不是 MSL 手动记的。

### 11.4 Follow-up 追踪系统

**"专家请求清单"（KOL Request Backlog）自动维护：**

```json
{
  "backlog": [
    {
      "request_id": "req_001",
      "expert_id": "expert_001",
      "expert_name": "张三",
      "created_from_visit": "v_20260610_001",
      "item": "Efgartigimod 日本真实世界数据",
      "type": "材料",
      "status": "待准备",
      "deadline": "2026-06-20",
      "owner": "李明",
      "notes": ""
    }
  ]
}
```

**状态流转：**

```
待准备 → 已发送 → 已收到反馈 → 已关闭
     ↓
   超时（deadline 过 3 天未更新）→ 红色警示
```

**Deadline 设置：** MSL 每次手动设置（不做自动建议）。

**展示位置：** MSL 工作台 → Follow-up 追踪标签页

**自动行为：**

- 每次回访前，系统自动检查该专家的 backlog，提示"还有 2 项待准备"
- 材料发送后，MSL 在系统中标记"已发送"，状态自动更新
- 专家反馈后，关联到原请求，形成闭环

### 11.5 拜访后信号提取

**LLM 自动从拜访记录中提取：**

| 信号类型  | 说明             | 去向                |
|:----- |:-------------- |:----------------- |
| 观念变化  | 专家对某疗法/证据的态度转变 | 全局信号库 + 专家档案      |
| 证据缺口  | 专家提到"还缺什么数据"   | 全局信号库 + 证据矩阵      |
| 竞争动态  | 专家提到竞品的使用体验    | 竞争情报库             |
| 未满足需求 | 专家想要但还没拿到的东西   | Follow-up backlog |
| 新合作机会 | 潜在的研究合作/演讲邀请   | 专家档案 + 团队面板       |

**提取方式：** 拜访记录提交后，LLM 自动分析 `discussion` 字段，生成 `new_signals` 数组。

### 11.6 团队信号汇总

**所有 MSL 的拜访信号由 LLM 聚合后，系统发现共性趋势：**

```
本周 MSL 团队拜访信号汇总：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔥 共性趋势（3+ 位 MSL 提到）：
  • "专家对补体抑制剂安全性关注度上升" — 5/8 位 MSL
  • "医保谈判时间窗口询问增多" — 4/8 位 MSL

📍 区域差异：
  • 华北：更关注长期随访数据
  • 华东：更关注与竞品头对头比较
  • 华南：更关注儿童适应症扩展

⚠️ 紧急信号：
  • 2 位专家提到某竞品不良反应案例 — 需医学部关注
```

**展示位置：** MSL 工作台 → 团队面板

### 11.7 页面结构（MSL 工作台）

```
MSL 工作台
├── 专家画像（列表+搜索+画像卡片）
├── 拜访助手
│   ├── 新建拜访
│   │   ├── 选择专家 → 自动加载画像
│   │   ├── 选择类型：新拜访 / 回访
│   │   ├── 系统自动生成简报（新拜访=画像+热点 / 回访=纪要+follow-up+衍生）
│   │   └── MSL 预览/调整简报 → 确认

## 八、关键设计原则（修订版）

1. **工作流优先于页面** — 先画用户（MSL/MA）的日常流程，再决定页面结构。不为了"页面好看"创造假模块
2. **信号驱动，不展示驱动** — Dashboard 回答"这周该干什么"，不是"这周发了多少文章"
3. **LLM 做提取不做生成** — 提取信号/归类/结构化这些"从无序到有序"的事交给 LLM；最终产出的内容和判断由人决定
4. **渐进可部署** — 每个阶段独立可用。阶段 1 做完 MSL 就能用专家画像，不等所有阶段完才上线
5. **中国优先** — 所有情报通道都有中国独立视角。中国的 MSL 团队不需要先看英文数据再手动翻译搬运
6. **反馈闭环** — MSL 的使用行为（谁看了什么、什么信号被关注了、什么模板最常用）反哺系统优化

### 10.2 专家识别方式

**方案 C：姓名+机构消歧 + 手动标注核心专家**

- 系统维护 `data/experts-core.json`（核心专家名单）
- 优先精确匹配核心专家，其余作者自动聚合
- 同名作者通过机构字段辅助消歧

**核心专家名单格式（`data/experts-core.json`）：**

```json
{
  "experts": [
    {
      "id": "expert_001",
      "name_zh": "张三",
      "name_en": "Zhang San",
      "affiliation": "北京协和医院",
      "tags": ["FcRn", "重症肌无力", "神经免疫"],
      "priority": "A",
      "msl_owner": "李明",
      "status": "active"
    }
  ]
}
```

- `id`：系统唯一标识
- `name_en`：用于 PubMed 匹配（authors 字段是英文）
- `tags`：手动标注的研究兴趣，帮助系统理解
- `priority`：A=核心（每月拜访）/ B=重要（季度拜访）/ C=一般
- `msl_owner`：负责维护关系的 MSL
- `status`：active / inactive / new — 支持动态变化

### 10.4 研究兴趣向量计算

**简单版（词频统计）：**

1. 提取该专家所有发文的标题+摘要
2. 分词 → 过滤停用词（MG, myasthenia, patient, study, etc.）
3. 统计词频（TF）
4. 取 top 10 作为研究兴趣向量
5. 每个兴趣附带"相关发文数"

**后续可升级：** TF-IDF 加权、LLM 主题提取。
